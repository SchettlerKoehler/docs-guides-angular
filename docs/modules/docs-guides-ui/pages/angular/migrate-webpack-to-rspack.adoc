[#migrate-webpack-to-rspack]
= Migrate an Nx Angular App from webpack to Rspack

This guide moves an Nx-based OneCX Angular application off `@angular-devkit/build-angular` and webpack to Rspack, with Module Federation configured directly through `@module-federation/enhanced/rspack`.
It follows the approach taken for `onecx-shell-ui` and for apps generated by the OneCX Angular generator (`onecx-nx-plugins`).

[#why]
== Why Migrate

* `@angular-devkit/build-angular` is deprecated on npm: "Angular's Webpack support is deprecated. Use the esbuild and Vite-based `@angular/build` package instead."
* Nx v23 deprecates the Module Federation wrappers in `@nx/module-federation/angular` (`withModuleFederation`, `NxModuleFederationPlugin`), and Nx v24 removes them. See https://nx.dev/docs/kb/migrate-angular-module-federation[Migrate Angular Module Federation off the Nx wrappers].
* Rspack keeps the webpack configuration model (plugins, loaders, `module.rules`), so custom build logic can be carried over. See https://nx.dev/docs/kb/migrate-from-webpack[Migrate Angular with Webpack to Rspack].

[#overview]
== Overview

[%header,cols="1,1,1"]
|===
| Concern | Before | After

| `build` target
| `@nx/angular:webpack-browser` with `customWebpackConfig`
| `@nx/rspack:rspack` with `rspack.config.js`

| `serve` target
| `@nx/angular:dev-server`
| `@nx/rspack:dev-server`

| Module Federation
| `withModuleFederation` from `@nx/module-federation/angular`, or `ModuleFederationPlugin` from `@module-federation/enhanced/webpack`
| `ModuleFederationPlugin` from `@module-federation/enhanced/rspack`

| Source patches
| `modify-source-webpack-plugin`
| Custom Rspack loader

| `extract-i18n` target
| Angular builder
| Angular builder, unchanged (see <<extract-i18n>>)
|===

[#prerequisites]
== Prerequisites

* The application is an Nx workspace. Nx 20.6.0 or newer provides the `convert-to-rspack` generator.
* The application builds and serves with its current webpack setup. You need it as a baseline.

[#capture-baseline]
== Step 1: Capture a Baseline

Before changing anything, run a production build and copy the generated `mf-stats.json` out of the `dist` folder.
It contains the container name, the `exposes` map and the `shared` entries that the new configuration must reproduce.

Also note what works today: the routes and remote components the shell loads from your app, and the port and public host of the dev server.

[#install-packages]
== Step 2: Install the Rspack Packages

Add the Rspack packages as dev dependencies. Use the same version for `@nx/rspack` and `@nx/angular-rspack` as for your other `@nx/*` packages.

[source,bash]
----
npm install --save-dev @nx/rspack @nx/angular-rspack @rspack/core
----

`@module-federation/enhanced` stays a dependency of the application.

[#swap-bundler]
== Step 3: Swap the Bundler

Nx provides a generator that converts an Angular webpack project to Rspack:

[source,bash]
----
npx nx g @nx/angular:convert-to-rspack
----

Whether you use the generator or convert by hand, the result is the same: the Angular build options move from `project.json` into an `rspack.config.js`, which builds the base configuration with `createConfig` from `@nx/angular-rspack`.

[#rspack-config]
=== The Rspack Configuration

The following example is based on the configuration the OneCX Angular generator creates.
Copy the values from your current `build` target options into `createConfig`. The `main` option is called `browser`.

.rspack.config.js
[source,javascript]
----
const { createConfig } = require('@nx/angular-rspack')
const { ModuleFederationPlugin } = require('@module-federation/enhanced/rspack')
const webpackMerge = require('webpack-merge')
const mfConfig = require('./module-federation.config')

const isProduction = process.env.NODE_ENV === 'production'

module.exports = async (_config, args = {}) => {
  // Resolved dev-server options (host, port, proxy, ...) passed by @nx/rspack:dev-server
  const executorDevServer = (args && args.options && args.options.devServer) || {}

  const baseConfig = await createConfig({
    options: {
      root: __dirname,
      index: './src/index.html',
      browser: './src/main.ts',
      polyfills: ['./src/polyfills.ts'],
      tsConfig: './tsconfig.app.json',
      inlineStyleLanguage: 'scss',
      assets: ['src/favicon.ico', 'src/assets'],
      styles: [{ input: 'src/styles.scss', bundleName: 'styles', inject: true }],
      fileReplacements: isProduction
        ? [{ replace: 'src/environments/environment.ts', with: 'src/environments/environment.prod.ts' }]
        : [],
      optimization: isProduction,
      sourceMap: !isProduction,
      outputHashing: isProduction ? 'all' : 'none',
      outputPath: { base: './dist/my-app', browser: '.' },
      extractLicenses: false
    }
  })

  return webpackMerge.merge(baseConfig[0], {
    devServer: {
      ...executorDevServer,
      allowedHosts: 'all',
      headers: { 'Access-Control-Allow-Origin': '*' }
    },
    plugins: [new ModuleFederationPlugin(mfConfig)],
    output: { uniqueName: 'onecx-my-app-ui', publicPath: 'auto' },
    experiments: { topLevelAwait: true, outputModule: true },
    optimization: { runtimeChunk: false, splitChunks: false }
  })
}
----

Notes:

* `webpack-merge` must be installed as a dev dependency if you use it to merge the configurations.
* `outputPath` with `browser: '.'` writes the build output directly into `dist/my-app` instead of a `browser` subfolder. Keep the output path your `Dockerfile` and build scripts expect.
* `extractLicenses: false` is set because the license plugin enabled by default fails under Rspack and aborts the production build.
* The `headers` entry lets the shell load `remoteEntry.js` from the dev server cross-origin.
* Move other plugins from your webpack configuration as well. Import them from `@rspack/core` (for example `DefinePlugin`) instead of `webpack`.

[#targets]
=== The `build` and `serve` Targets

Point the targets at the Rspack executors. The `build` target only keeps what the executor reads directly; `mode` sets `NODE_ENV`, which selects the production settings in `rspack.config.js`.

.project.json
[source,json]
----
"build": {
  "executor": "@nx/rspack:rspack",
  "options": {
    "outputPath": "./dist/my-app",
    "index": "src/index.html",
    "tsConfig": "tsconfig.app.json",
    "rspackConfig": "rspack.config.js"
  },
  "configurations": {
    "development": { "mode": "development" },
    "production": { "mode": "production" }
  }
},
"serve": {
  "executor": "@nx/rspack:dev-server",
  "options": {
    "buildTarget": "my-app:build",
    "host": "0.0.0.0",
    "publicHost": "http://localhost:4200",
    "proxyConfig": "proxy.conf.js"
  }
}
----

Alternatively, let Nx infer the `build` and `serve` targets from the Rspack configuration by registering `@nx/rspack/plugin` in `nx.json`, as `onecx-shell-ui` does with its `rspack.config.ts`:

.nx.json
[source,json]
----
"plugins": [
  {
    "plugin": "@nx/rspack/plugin",
    "include": ["rspack.config.ts"],
    "options": {
      "buildTargetName": "build",
      "serveTargetName": "serve"
    }
  }
]
----

[#proxy-config]
=== The Proxy Configuration

The Rspack dev server only accepts the array form of the proxy configuration. Convert each keyed entry into an array entry with a `context`:

.proxy.conf.js
[source,javascript]
----
const PROXY_CONFIG = [
  {
    context: ['/bff'],
    target: 'http://my-app-bff',
    secure: false,
    pathRewrite: { '^.*/bff': '' },
    changeOrigin: true
  }
]

module.exports = PROXY_CONFIG
----

[#module-federation]
== Step 4: Configure Module Federation Directly

[#mf-enhanced-webpack]
=== Apps Using `@module-federation/enhanced/webpack`

Apps created by the OneCX Angular generator already use `ModuleFederationPlugin` from `@module-federation/enhanced` with a separate `module-federation.config.js`.
Keep that file and import the plugin from `@module-federation/enhanced/rspack` instead of `@module-federation/enhanced/webpack`, as shown in <<rspack-config>>.

[#mf-nx-wrapper]
=== Apps Using the Nx Wrapper

If the app uses `withModuleFederation` from `@nx/module-federation/angular`, Nx no longer derives the configuration for you. Write it out by hand from the baseline `mf-stats.json`:

* `name`: the container name from the baseline.
* `exposes`: the existing `exposes` map.
* `shared`: the shared entries. Use `getOneCXSharedLibraryConfig` from `@onecx/build-utils` instead of copying every entry, see xref:documentation:docs-guides-ui:setup/required/configure-remote-package-sharing.adoc#automatic-package-sharing[Automatic Package Sharing].
* `shareScope`: the share scope the wrapper received, for example `angular_21`.

.module-federation.config.js
[source,javascript]
----
const { getOneCXSharedLibraryConfig } = require('@onecx/build-utils')
const { dependencies } = require('./package.json')

module.exports = {
  name: 'onecx-my-app-ui',
  filename: 'remoteEntry.js',
  library: { type: 'module' },
  exposes: {
    './OneCXMyAppModule': './src/main.ts'
  },
  shared: getOneCXSharedLibraryConfig(dependencies, true),
  shareScope: 'angular_21'
}
----

Pass this object to `ModuleFederationPlugin` in `rspack.config.js`, and set `output.uniqueName`, `output.publicPath: 'auto'` and `optimization.runtimeChunk: false` as shown in <<rspack-config>>.
Then delete the old `webpack.config.*` files.

[#source-patches]
== Step 5: Replace Source Patches with an Rspack Loader

If your webpack configuration patches third-party sources with `modify-source-webpack-plugin`, reimplement each patch as a small Rspack loader. A loader receives the source of every module its rule matches and returns the transformed source.

.source-patch.loader.js
[source,javascript]
----
module.exports = function sourcePatchLoader(source) {
  // Same search and replacement as the former ReplaceOperation('all', ...)
  return source.replace(/searchPattern/g, 'replacement')
}
----

Register the loader with a rule that only matches the package to patch:

.rspack.config.js
[source,javascript]
----
module: {
  rules: [
    {
      test: /[\/\\]node_modules[\/\\]some-package[\/\\]/,
      enforce: 'pre',
      loader: require.resolve('./source-patch.loader.js')
    }
  ]
}
----

* Restrict `test` to the package path, so other modules are not rewritten.
* If you had several patches, check `this.resourcePath` inside the loader to apply each replacement only to its package.
* The search strings depend on the patched package's code. After updating that package, check the built bundle to confirm the replacement still applies.
* Remove `modify-source-webpack-plugin` and other webpack-only packages once nothing imports them.

[#extract-i18n]
== Step 6: Keep `extract-i18n` on an Angular Builder

There is no Rspack-based i18n extraction. Keep the `extract-i18n` target on an Angular builder, and keep `@angular-devkit/build-angular` as a dev dependency only for this target.

The extractor reads the options of its `buildTarget` and runs an Angular build with them, so it cannot use the Rspack `build` target. Add a separate build target that only serves the extraction, as `onecx-shell-ui` does:

.project.json
[source,json]
----
"build-i18n": {
  "executor": "@angular-devkit/build-angular:browser",
  "options": {
    "outputPath": "dist/my-app-i18n",
    "index": "./src/index.html",
    "main": "./src/main.ts",
    "polyfills": ["zone.js"],
    "tsConfig": "./tsconfig.app.json",
    "inlineStyleLanguage": "scss"
  }
},
"extract-i18n": {
  "executor": "@angular-devkit/build-angular:extract-i18n",
  "options": {
    "buildTarget": "my-app:build-i18n"
  }
}
----

Copy the remaining build options (assets, styles) from your former `build` target, and remove `customWebpackConfig` from the `extract-i18n` options.
The extractor also requires `@angular/localize` as a dev dependency.

[#verify]
== Step 7: Verify the Migration

* Build with the `production` and `development` configurations, without the Nx cache (`--skip-nx-cache`).
* Check that `remoteEntry.js` and the global styles are in the output folder.
* Compare the container name, `exposes` and `shared` entries in the new `mf-stats.json` with the baseline.
* Serve the app and load it through the shell: the remote modules and remote components render without Module Federation errors in the browser console.
* Run `extract-i18n` and the unit tests.
